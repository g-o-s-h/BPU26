# C++ 从入门到入土

## 课程目标
- 让你逐步拥有独立学习，独立 Debug，独立开发的能力，基于 C++，但不止于 C++。
- 让你适应带有逻辑的思考方式，辩证地看待事物，并学会质疑。
- 让你逐步拥有向他人传授自己知识的能力。
- 让你能随手使用 C++ 解决日常生活中的问题。
- Extra Task: 取得一定的竞赛 & 开发成果，有助于申请季拿下 CS 专业 Top 10 甚至 Top 3。
---
## 课程形式
- 前几节课：手把手带着上道
- 后续课上：大致告诉我需要答疑的“内容范围”，课上仅做答疑，解决自学后的遗留问题；大约 1 - 2 周一节课（如果一周积累的问题不够多就顺延到下一周，如果太多了可能会周中再加一节，或者增加课时）
- 后续课下：从一开始课下复习课上知识，到之后可以自学我提供的材料，到最后可以自己找资源、自学、实践、辩证思考资料是否准确。
- 作业：由于 CS 这门学科 “一切以计算机执行的结果为准；输出结果是错的，它就不可能是对的” 的特性，作业不需要人工批改，因此大致有以下几种作业形式：
    1. 洛谷直接刷题，有问题“就题论题”
    2. 自学一定的内容，写一段实践代码，有问题“就代码论代码”
    3. 逐步能对自己“哪里没掌握”做出准确判断
    4. 其他，譬如梳理一个知识点的逻辑结构等

1. 空间效率：
   - `std::string`：使用 `std::string` 存储数字时，每一个数字位都占用一个字符的空间。因此，对于一个 N 位的数字，需要额外的 N 个字符存储。这样的实现相对较为简洁，不需要预先确定数组的长度，而且可以动态适应数字的位数。
   - `int` 数组：使用 `int` 数组存储数字时，每一个数组元素通常表示一位数字（比如采用十进制，每个元素范围为0-9）。因此，对于一个 N 位的数字，需要定义一个长度为 N 的数组来存储。这种实现需要预先确定数组的长度，并且会占用更多的空间。

综合考虑，从空间效率的角度来看，使用 `std::string` 可能更加划算，因为它可以根据实际位数进行动态分配，避免了不必要的空间浪费。

2. 时间效率：
   - `std::string`：使用 `std::string` 进行高精度计算时，每一位的操作都需要涉及字符串的拼接、截取、转换等操作。这些操作可能会导致频繁的内存分配和拷贝，对于大规模的高精度计算，时间效率可能较低。
   - `int` 数组：使用 `int` 数组进行高精度计算时，可以直接通过数组元素进行运算，无需进行字符串操作。这样的实现通常更加高效，尤其是对于大规模的高精度计算。

综合考虑，从时间效率的角度来看，使用 `int` 数组可能更加划算，特别是在需要进行大规模高精度计算时。

总结：
使用 `std::string` 或 `int` 数组都可以实现高精度计算，但从空间效率和时间效率的角度来看，`std::string` 在空间方面更加灵活和节省，而 `int` 数组在时间方面更加高效。根据你的具体需求和使用场景，选择适合的方案。如果需要进行大规模的高精度计算，且对空间要求不敏感，那么使用 `int` 数组可能更合适；如果对空间要求敏感，或者数字位数较小且需要频繁变动，那么使用 `std::string` 可能更合适。 -->
