### 万年历代码演进路径

1. **最初的笨办法**：
   - `get_day` 用冗长的 `switch-case` 判断每个月多少天
   - `get_offset` 用两重 `for` 循环，老老实实一年一年、一月一月把天数加起来
   - 缺点：年份一远，循环就跑得越多，比较呆板

2. **偏移量取模优化**：
   - 最初判断换行是 `i % 7 == (7 - skip) % 7`，绕来绕去
   - 后来改成了 `(i + offset) % 7 == 0`，意思就是“前面的空格数 + 当前日期，凑满 7 的倍数就换行”，看着直观多了

3. **查表代替 `switch`**：
   - 把每个月的天数和累计天数直接写进两个 `static const` 数组里（`day_table` 和 `day_accumulate`）
   - 用的时候按索引直接拿，不仅代码短，跑得也快

4. **用公式优化掉推理的循环**：
   - 发现算总天数根本不需要循环，直接套用闰年公式 `(year-1)/4 - (year-1)/100 + (year-1)/400` 就能算出中间经历了多少个闰年
   - 一次乘除直接算完，效率拉满

5. **支持 1900 年以前的日期（负轴，解决取模问题）**：
   - 之前为了只算现代日历，只做了正数运算。后来发现把 `year` 传负数进来，只要处理一下“C语言负数取模会得负数”的坑就行
   - 用 `(a % 7 + 7) % 7` 这个经典小技巧，硬生生把负数天数掰回了正确的星期位置，现在连公元前都能算了
